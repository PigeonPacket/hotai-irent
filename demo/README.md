# iRent 車況拍照引導｜可點擊原型

和泰 iRent 黑客松 · PigeonPacket（PIG-5），對應 [PIG-13 UX Flow](../docs/PIG-13-UX-Flow.md)。

**不接後端、全部模擬資料**，目標是簡報時一鏡到底走完八個畫面：
取車前預告 → 取車引導拍照 → 補拍窗口 → 使用中回報 → 還車拍照 → 模擬 AI 前後比對 →
爭議事證包 → 積分結算（另可隨時翻到營運視角）。

vanilla JS + ES modules，**零依賴、零 build step**。

---

## 啟動

```bash
cd demo
python3 -m http.server 8080
```

開 <http://localhost:8080/>（沒有 hash 時會自動導到劇本第一站 `#/vehicle`）。

簡報常用網址：

```
http://localhost:8080/?mock=1&nav=1&speed=fast
```

> **不能用 `file://` 開** —— ES modules 需要 `http://`。

### ⚠️ 相機需要 HTTPS 或 localhost

瀏覽器只在 **secure context** 下給 `getUserMedia`：

| 開啟方式 | 相機 |
|---|---|
| `http://localhost:8080`（電腦本機） | ✅ 可用 |
| `http://127.0.0.1:8080` | ✅ 可用 |
| `https://…`（任何 HTTPS 通道） | ✅ 可用 |
| **`http://192.168.x.x:8080`（手機連區網 IP）** | ❌ **開不了相機** |

**用手機連電腦的區網 IP 是拿不到相機的** —— 這是瀏覽器的安全限制，不是 bug。
`camera.js` 會**自動降級成模擬相機**（畫面左上角出現「模擬相機」標記），
整條劇本仍然可以完整點完，只是拍到的是模擬素材而不是真實鏡頭。

要在手機上用**真實相機**，必須開一條 HTTPS 通道，例如：

```bash
npx localtunnel --port 8080      # 或 ngrok http 8080
```

然後用它給的 `https://…` 網址開，**且不要帶 `?mock=1`**。

## 八個畫面

| # | 畫面 | 路由 | 說明 |
|:-:|------|------|------|
| 1 | 取車前車況預告 | `#/vehicle` | AI 綜合上一輪還車紀錄：整潔度 / 油量 / 已知舊損 / 風險標籤 / 換車 |
| 2 | 取車：四角引導拍照 | `#/capture?phase=pickup` | 左前 → 右前 → 左後 → 右後，橫向 4:3，品質提示非阻擋 |
| 3 | 開鎖後補拍窗口 | `#/supplement` | 15 分鐘倒數，四類補拍：車內整潔 / 異味垃圾 / 重拍某角 / 新發現損傷 |
| 4 | 使用中回報 | `#/inuse` | 被動畫面；可隨時回報車況異常 → 模擬 AI 初判 → **即時改車輛狀態** |
| 5 | 還車：四角引導拍照 | `#/capture?phase=return` | 與 #2 同一套 UI，文案改為還車 |
| 6 | AI 前後比對（模擬） | `#/compare` | clean / suspect / damage 三分支 + 誠實申報減免 |
| 7 | 爭議 · AI 客服管家 | `#/dispute` | 彙整事證鏈 → 對話式引導 → 產出事證包 JSON |
| 8 | 積分結算 | `#/settlement` | 積分明細、折抵金額、分數階梯 |
| — | 營運視角 · 車隊狀態 | `#/ops` | 車輛狀態機、下一位使用者看到什麼（側視角，非主線） |

畫面模組一個檔案一支：`src/screens/<id>.js`，**建立檔案 = 自動上線**（`app.js` 用
`fetch(HEAD)` 探測，不存在就安靜略過）。細節見 [`src/CONTRACT.md`](src/CONTRACT.md)。

## URL 參數

### 主 App（`index.html`）

| 參數 | 用途 |
|------|------|
| `?mock=1` | 強制模擬相機。**沒有相機 API、非 HTTPS/localhost、或使用者拒絕授權時會自動啟用**，筆電上可完整點完 |
| `?nav=1` | 顯示簡報跳頁列（畫面底部），可跳過任一段，最右邊有「重置」 |
| `?speed=fast` | 時間壓縮：**1 真實秒 = 1 demo 分鐘**。補拍 15 分鐘倒數變 15 秒，各處模擬延遲也一起變快，但畫面文案仍顯示分鐘制 |
| `?scenario=clean\|suspect\|damage` | 強制 `#/compare` 的判定分支。不帶就依**實際拍照行為**推導 |
| `?reset=1` | 開機清空 localStorage session |

### 畫面專屬

| 參數 | 用途 |
|------|------|
| `#/capture?phase=pickup\|return` | 取車 / 還車兩個入口共用同一支模組。非 `return` 一律視為 `pickup` |
| `#/compare?force=auto\|clean\|suspect\|damage` | **畫面內**覆寫比對結果，不用重載頁面。覆寫優先序：`?force=` > `?scenario=` > 行為推導 |

### 輪廓驗證頁（`guide-lab.html`，獨立頁面）

| 參數 | 用途 |
|------|------|
| `?corner=lf\|rf\|lr\|rr` | 指定起始角度 |
| `?mode=calib` | 直接進「鏡頭視野校正」模式 |
| `?mock=1` | 強制模擬相機（**只認 `=1`**；不帶這個參數就是嘗試真相機） |

## 3 分鐘演示劇本

開 `http://localhost:8080/?mock=1&nav=1&speed=fast`，從 `#/vehicle` 開始。
下面每一步的**按鈕文字都是畫面上的原字**，照著點就好。

> `?nav=1` 的跳頁列是保險絲：任一段卡住就直接跳下一站，不要在台上除錯。
> 跳頁列順序即劇本順序：`1 取車前預告 · 2 取車拍照 · 3 補拍窗口 · 4 使用中回報 ·
> 5 還車拍照 · 6 AI 比對 · 7 爭議／事證包 · 8 積分結算 · 9 營運視角 · 重置`。

### ① 取車前預告 · 0:15 `#/vehicle`

- 講點：「上一位還車後，AI 已經把車況整理好了 —— 整潔度、油量、**3 處已知舊損**（車體俯視圖上有編號標記）。」
- 指出卡片 **「🛡️ 為什麼要你先花 40 秒拍照？」**：先講自保，積分是次要動機。
- 點 **`繼續取車，開始四角拍照`**。

### ② 取車四角拍照 · 0:35 `#/capture?phase=pickup`

- 講點：站位提示 **`📏 站位：手機橫向、胸口高度（約 1.5 m），退到約 5 步（3.85 m）外，讓全車落進虛線`**
  —— 這個距離是**算出來的**，不是設計偏好（PIG-13 §1.2）。
- 四角固定順序：**左前 45° → 右前 45° → 左後 45° → 右後 45°**，頂部進度條顯示 `1/4`。
- 每一角：點 **`拍攝`** → 進預覽 → 點 **`確認，下一角`**。
  （想演「非阻擋」就點 **`先繼續（積分較少）`** 跳過某一角 —— 之後 `#/compare`
  會因此變成 suspect 分支，這是**故意留的伏筆**。）
- 四角都完成後才會出現底部區塊，點 **`完成取車拍照`**。

> 電腦上不會跳「請把手機轉成橫向」提示（偵測用 `screen.orientation`）。
> 手機直向時才會出現，而且**不擋操作**，可以按 `仍以直向繼續`。

### ③ 補拍窗口 · 0:25 `#/supplement`

- 倒數從 `15:00` 開始跑。`?speed=fast` 下 **15 秒就跑完**，文案仍寫「分鐘」——
  這是刻意的，示範時間壓縮不影響文案正確性。
- 點 **`🧼 車內整潔`**（需要 3 張：前座 / 後座 / 置物空間），拍 1–3 張，每張點 **`採用，併入租前基準`**。
- 講點：補拍照片**併進租前基準**並標時間戳，逾時後只能走客服通報（非正式存證鏈）。
- 點 **`完成補拍，開始用車`**（趕時間就點 **`跳過補拍`**）。

> 想演逾時：等倒數跑完，畫面會換成
> **`🔒 補拍窗口已關閉（解鎖後 15 分鐘）…`** + 客服通報表單，
> 上面有 **`重新開窗（demo 用）`** 可以復原。

### ④ 使用中回報 · 0:25 `#/inuse`

- 點 **`回報車況異常`** → 選 **`🔧 車損 / 刮傷`** → 說明欄可留白 → 點 **`送出回報`**。
- 出現 **`模擬 AI 初判中…`**（`?speed=fast` 下約 0.45 秒）→ 結果卡顯示 `車輛狀態 舊 → 新`。
- 講點：**這一刻車輛狀態就變了**，下一位使用者在預約清單立刻看得到（等一下在 `#/ops` 驗證）。
- 點 **`前往還車拍照`**。

> 沒有照片也送得出去（非阻擋），但模擬 AI 會標「無法初判，只會轉人工」。
> 勾 **`可能影響行車安全`** 一律變成「不建議出租」。

### ⑤ 還車四角拍照 · 0:20 `#/capture?phase=return`

- 同一套 UI，文案換成 **`🛡️ 還車前拍照，證明你交還時車況正常`**。
- 快速拍完四角（或用 `先繼續（積分較少）` 加速）→ 點 **`完成還車拍照，開始 AI 比對`**。

### ⑥ AI 前後比對 · 0:30 `#/compare`

- 四步動畫（`載入取車基準 → 對齊四角視角 → 比對差異區域 → 產生判定`），趕時間點 **`跳過動畫`**。
- 判定**不是固定腳本**：依你剛剛的拍照行為推導。第 4 步回報過車損 → `damage`；
  有跳過或品質警告 → `suspect`；都拍好 → `clean`。
- 要現場切換分支：展開 **`簡報工具：強制分支`**，點 `無新增損傷 / 疑似／複審 / 明顯新增` 即時切換（不用重載）。
- 演 `damage` 時點 **`誠實申報：這是我造成的`**（+5 積分，留在本頁）再點 **`完成還車，結算積分`**；
  要演爭議就點 **`我有爭議，要說明`** 進 ⑦。
- 展開 **`判定依據（模擬規則，可展開給評審看）`** 可以主動說明「這是寫死的規則不是真推論」。

### ⑦ 爭議與事證包 · 0:20 `#/dispute`

- 上方自動顯示彙整結果與**五段事證鏈**（取車基準 / 補拍窗口 / 使用中回報 / 還車存證 / AI 判定），
  各自標 `有存證` / `不足` / `缺漏`。
- 點一個爭議理由 chip（例：**`這個刮痕取車時就有`**）→ 點 **`送出給 AI 客服管家`**。
- 三段回覆後自動捲到 **`④ 事證包`**：JSON 只含 metadata 不含影像。
- 點 **`前往積分結算`**。

### ⑧ 積分結算 · 0:15 `#/settlement`

- 講點：**`分數階梯（為什麼「亂拍」不會比較划算）`** —— 全跳過 10 分、有警告 20 分、
  四角品質達標 40 分、加補拍與誠實申報最高 55 分。積分換算 **1 積分 = NT$0.5（假設值）**。
- 收尾：**`你的存證資產`** 卡片 —— 這一整輪拍的所有照片就是使用者的自保資產。

### ⑨（有時間才翻）營運視角 · 0:15 `#/ops`

從 `#/settlement` 的 **`營運視角`**（或 `#/inuse` 的 **`查看營運視角`**）進去：

- 卡片 **`這一頁在證明什麼`** 會顯示 `本次 session：最新回報 … → 車輛狀態更新延遲 N 秒`
  —— 直接呼應第 4 步。
- **`車輛狀態機`** 圖上高亮目前節點；車隊清單每張卡下方是
  **`下一位使用者在預約清單會看到什麼`** 的模擬預約卡。
- 卡片 **`Demo 工具 · 直接寫入 flags.vehicleStatus`** 可以現場示範別名解析與不合法值的優雅退化。

### 重跑

跳頁列最右邊的 **`重置`**，或 `#/settlement` 的 **`重跑一次完整劇本（清空 session）`**，
或直接在網址加 `?reset=1`。

## `guide-lab.html` —— 車體輪廓驗證頁

獨立頁面（不走主 App 的 router），用途是**拿手機站在真的 Toyota Corolla Cross 前面**，
三分鐘內判斷：(1) 我們產的輪廓對不對得上實車、對得上的相機參數是哪一組；
(2) 內部細節線要哪一級密度；(3) 交付用 iRent 專屬版還是 Monk BSD 版。

```bash
cd demo && python3 -m http.server 8091
# 電腦：http://localhost:8091/guide-lab.html
# 手機：需 HTTPS 通道（見上方「相機需要 HTTPS 或 localhost」）
```

### 基準相機參數

輪廓與參考渲圖是用**同一組**相機參數產生的
（`assets/car-reference/generated/build-report.json`）：

| 參數 | 值 |
|---|---|
| 水平距離 | **3.85 m**（量到**車體中心地面投影點**，不是保桿 —— 離最近車角其實只有約 1.9 m） |
| 相機高 | **1.5 m**（胸口平舉） |
| 方位角 | **45°**（四角分別 45 / 315 / 135 / 225°） |
| 等效焦距 | **26 mm**（hFOV 69.39° / vFOV 54.88°） |
| 畫面 | **4:3 橫向**，viewBox 500×375 |
| 車輛 | Toyota Corolla Cross XG10（4460 × 1825 × 1620 mm、軸距 2640 mm） |

面板上的相機滑桿是**近似重投影**（單應性），不是真 3D 重算：基準值時完全恆等（誤差 0），
焦距是精確的，距離與相機高只有一階近似，**偏擺最弱** —— 面板裡有寫，判讀時請照著看。
「站位敏感度」摺疊區有完整的誤差表（來源與方法見 [PIG-13 §1.2](../docs/PIG-13-UX-Flow.md)）。

### 鏡頭校正模式（`?mode=calib`）——**出門前在室內先做一次**

整套輪廓假設等效焦距 26 mm，但：

- 各家手機主鏡頭落在 **23–28 mm**；
- 更麻煩的是 `getUserMedia` 給的**串流視野常常跟相機 App 拍照的視野不一樣**
  （額外裁切、防手震邊界、不同的 sensor crop），所以「EXIF 寫 26 mm」不能當串流的焦距。

沒校過的話，你站對位置卻覺得輪廓對不上，然後**誤判成輪廓錯了**。
這個模式存在的唯一目的，是把「鏡頭問題」和「輪廓問題」分開。

**什麼時候用**

1. **出門前，在室內先量一次**（一分鐘的事）—— 找一道門框、桌上的 A4 或紙箱當已知寬度物件。
2. **到了車前覺得「怎麼喬都對不上」時，再量一次** —— 拿 A4 紙貼在車門上當已知寬度就行。

**怎麼用**（三步，畫面上就是這樣標的）

1. 拿一個**已知寬度**的東西正對鏡頭，用捲尺量它到手機的距離，填入「物件實寬」與「量測距離」。
2. 把畫面上兩條線拖到物件的**左右外緣**（點畫面也會把最近的一條移過去）。
3. 看結果 → 點 **`套用 … mm 到焦距滑桿`**，或點 **`採用這次校正（記住）`**
   把結論存進這支手機的 `localStorage`。

> 沒有捲尺就用 A4 長邊（29.7 cm）接力量距離，**不要用步伐**。
> 這個量測假設鏡頭無畸變、物件平面垂直光軸且大致置中 —— 畫面會把不確定度拆開列給你看，
> 偏差比量測誤差還小的時候它會直接告訴你「這個差異不顯著」。

## 結構

```
index.html      app shell（header / #screen / footer）
app.js          入口：註冊八個畫面模組 + 開機
styles.css      設計 token + 共用元件 kit（畫面專屬 CSS 跟著模組走）
src/
  config.js     URL 參數 + 時間壓縮 helper
  state.js      session 狀態 + localStorage（照片自動降階成縮圖）
  router.js     hash 路由 + 畫面生命週期 + 跳頁列
  camera.js     相機 / 模擬相機（永不 throw，失敗自動降級）
  quality.js    亮度・過曝・梯度模糊・輪廓占比啟發式 + STANDING_GUIDE
  guides.js     四角定義（正式契約）+ 真實車體輪廓（密度／相機常數在檔頭）
  guides-cuv.js Corolla Cross 四角折線資料（自動產生，勿手改）
  vehicle-status.js  車輛營運狀態機（VEHICLE_STATUS / STATUS_META / normalizeStatus）
  points.js     積分規則（對齊 PIG-13 §5）
  screens/      一個檔案一個畫面（八支）
  CONTRACT.md   ← 要加畫面 / 改共用模組的人先讀這個（含「已知技術債」）
guide-lab.html  車體輪廓驗證頁（獨立，不走 router）
guide-lab/      驗證頁的模組：geom / sources / labcam / calib / calibui / main
assets/         模擬素材（car-<角度>.jpg 會自動被模擬相機採用）
  README.md     ← 素材清單、**第三方授權標示**、品質量測實測值（直向＋橫向）
  car-reference/ 研究素材（3D 模型、Commons 照片、產生的輪廓 SVG）—— **非執行時資源**
```

**要加新畫面 / 修改共用模組前，請先讀 [`src/CONTRACT.md`](src/CONTRACT.md)。**

## 誠實邊界（簡報前請先看過）

- 🟡 **虛線輪廓已是真實 Corolla Cross 幾何，但密度與站位仍是暫定值。**
  `src/guides.js` 現在用的是 `assets/car-reference/generated/guide-cuv-*.svg`
  的實際車體折線（烘在 `src/guides-cuv.js`）。密度預設「中等」（36 條細節線 + 5 條地面線）、
  相機基準 3.85 m / 1.5 m / 偏擺 45° / 等效 26 mm，**兩者都要等 G5 站到實車前確認**，
  常數放在 `guides.js` 檔頭（`GUIDE_DENSITY` / `GUIDE_CAMERA`）。
- 🟠 **桌機模擬相機的取景與輪廓差 17.6%。** `assets/car-*.jpg` 是渲圖裁掉 15% 邊界做的，
  等效焦距因此是 30.6 mm 而不是輪廓假設的 26 mm，於是輪廓看起來比車小一圈、
  取景檢查會誤報「往後退約 5 步」。**真機不受影響**（真相機就是 26 mm 等效）。
  詳見 `src/CONTRACT.md` §10.2。
