# PIG-8｜實測前準備：iRent 租車體驗觀察清單

> 目的：在實際去做一次 iRent 租還車體驗**之前**先準備好，讓這趟實測能一次蒐齊
> （1）痛點第一手證據、（2）AI 車況辨識的影像素材、（3）流程量化數據。
> 對應 Linear：[PIG-8](https://linear.app/pigeonpacket/issue/PIG-8)　｜　痛點假設見 [痛點地圖](./PIG-8-租還車痛點地圖.md)

---

## 0. 為什麼要先準備
iRent **會員審核要隔天才知結果**（痛點 R1）。若到現場才註冊，當天租不到車。
👉 **最遲在實測前 2–3 天完成註冊與審核**，否則整個行程作廢。

---

## 1. 行前準備清單（Checklist）

### 帳號與證件（最優先，需提前 2–3 天）
- [ ] 完成 iRent 註冊與會員審核（記錄：審核花多久、是否被退件、退件原因）
- [ ] 準備證件：身分證、駕照、信用卡
- [ ] 確認帳戶有足夠額度（預約會先扣款，痛點 B4）
- [ ] 截圖保存註冊/審核每一步畫面（首次體驗也是痛點來源）

### 設備
- [ ] **手機 A**：實際操作 App（主帳號）
- [ ] **手機 B**：全程錄影/側拍記錄（不干擾操作流程）
- [ ] 行動電源、車充
- [ ] 碼錶/計時 App（記錄各階段耗時）

### 規劃
- [ ] 選定取車點與還車點（建議：取車與還車**不同站**，才能踩到還車點滿/找車位的痛點 B2）
- [ ] 預估時段（建議涵蓋一次「離峰時段還車」，對照清晨還車異常的負評 B1）
- [ ] 設定預算上限、記錄計費規則（時租/里程/逾時 3,000 元調度費）
- [ ] 分工：操作者 / 記錄者 / 拍照者（可重疊）

---

## 2. 拍照規範（給 AI 車況辨識當素材，務必統一）
> 取車與還車**用同一套拍法**，才能讓 AI 做前後比對（對應主打功能）。

每次（取車一輪、還車一輪）固定拍：
- [ ] **車身四角**（左前 / 右前 / 左後 / 右後 45°）
- [ ] **四面**（正前 / 正後 / 左側 / 右側）
- [ ] **儀表板**：里程數、油量/電量（讀數要清楚）
- [ ] **車內**：前座、後座、置物空間（記錄整潔度/垃圾/異味）
- [ ] **既有損傷特寫**：每一處刮痕/凹痕近拍 + 帶一張遠景定位
- [ ] 刻意拍幾組「不良範例」：角度不足、光線不夠、反光、模糊 —— 用來測 PIG-5 的「拍照引導/重拍提示」

📌 拍照時記錄：光線條件、距離、是否需要蹲下/繞車，評估「真實使用者願不願意這樣拍」。

## 4. 客服/異常情境（可選，若遇到就記）
- [ ] 嘗試文字客服與電話客服各一次，記錄等待時間與是否解決
- [ ] 若遇 App 異常/還車失敗，完整記錄畫面與時間軸（這是最珍貴的素材）

## 5. 實測後產出（回填到痛點地圖）
1. 用第一手數據**驗證/推翻**痛點地圖中的嚴重度與頻率假設。
2. 整理出取/還車各階段的**量化基準**（步驟數、秒數）——做為 Demo 中「AI 前後對比」的數字。
3. 把拍到的車況照片整理成 **AI 車況辨識的測試資料集**（含損傷/髒污/良好三類），交棒 [PIG-12](https://linear.app/pigeonpacket/issue/PIG-12)。
4. 回頭校正 [PIG-10 RICE](./PIG-10-核心功能RICE評估.md) 的 Reach / Effort 假設。
