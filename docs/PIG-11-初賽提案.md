## 1. 問題定義

### 1.1 市場與題目

- **賽事**：2026 和泰 AI 黑客松
- **對象**：和泰 iRent 共享汽車租還車體驗
- **市場地位**：iRent 車輛數與據點領先，但用戶體驗在多項基礎指標上落後唯一直接競品 **格上 GoSmart**（見 [PIG-9](./PIG-9-競品分析.md)）

### 1.2 用戶痛點（桌面研究 + 實測驗證）

兩條主線（[痛點地圖](./PIG-8-租還車痛點地圖.md)）：

| 主線 | 表現 | 嚴重度 |
|------|------|:------:|
| **車況爭議** | 取車無有效存證 → 還車被歸責；損傷/扣款爭議 | 高 |
| **孤立無援** | App 異常無法還車；客服難接通；爭議需自行整理事證 | 高 |

### 1.3 實測新證據（2026/07/02）

[實測報告](./PIG-8-實測報告.md) 指出更底層問題：

1. **拍照無引導、無品質檢查** → 存證素材不可靠（根因）
2. **使用者可亂拍即過** → 缺乏防禦性動機與獎勵機制
3. **租車後無法補拍車內等細節** → 流程缺口
4. **車損回報不即時** → 下一位使用者到場才踩雷（營運損失）

> **洞察**：GoSmart 已用「人工拍照存證」補課；iRent 若只做同一件事只是追平。機會在 **AI 自動判斷、前後比對、爭議仲裁**（[PIG-9 §3](./PIG-9-競品分析.md)）。

## 2. 解決方案

### 2.1 方案總覽

**主打：AI 車況辨識** — 取車建基準、還車 AI 比對、標記新增損傷。

**輔助：AI 客服管家** — 爭議或異常時即時介入、自動整理事證包。

完整故事線（[PIG-10](./PIG-10-核心功能RICE評估.md)）：

```
取車 AI 引導拍照 → 建立車況基準（含補拍窗口）
    → 還車 AI 引導拍照 → 自動前後比對
    → 有爭議 → AI 客服管家整理事證 → 降低人工負載
```

### 2.2 關鍵 UX 創新（實測驅動）

| 機制 | 說明 | 文件 |
|------|------|------|
| 虛線輪廓拍照引導 | 非阻擋式，提高四角 cover 品質 | [PIG-13](./PIG-13-UX-Flow.md)、[`demo/`](../demo/) |
| 防禦 + 獎勵雙軌動機 | 存證自保 + 積分折抵 | PIG-13 §5 |
| 15–30 分鐘補拍窗口 | 車內髒污等開鎖後才能發現的問題 | PIG-13 Screen 2 |
| 即時車輛狀態 | 問題車第一時間標記，下一位預告 | PIG-13 §4 |

### 2.3 初賽不主打（延伸藍圖）

個人化推薦、智能調度、智能車況預測 — RICE 分數低或缺資料（[PIG-10 §2](./PIG-10-核心功能RICE評估.md)）。

## 3. 技術可行性

### 3.1 架構（初賽 Prototype）

```
[PIG-5 前端] 相機引導 + 四角流程
      ↓ 影像 + metadata
[PIG-6 後端] Vision API 分析（損傷/髒污/油電量）
      ↓
[比對引擎] 取車基準 vs 還車影像 → diff 標記
      ↓ 爭議
[PIG-10 輔助] LLM + RAG 客服管家
```

### 3.2 技術選型（待 PIG-12 定稿）

| 層級 | 黑客松建議 | 說明 |
|------|------------|------|
| 拍照品質 | 前端輕量啟發式 + Vision 複核 | 見 `demo/app.js` |
| 車況辨識 | GPT-4o / Claude Vision | Demo 可行，明顯損傷/髒污可達標 |
| 客服 | LLM + RAG（FAQ/條款） | 成熟、可控 |

**風險**：細微刮痕精準度有限 — 初賽聚焦「明顯損傷 + 完整故事」而非 100% 自動定責。

### 3.3 現有產出

- 前端 PoC：[`demo/`](../demo/)（PIG-5）
- UX Wireflow：[PIG-13](./PIG-13-UX-Flow.md)
- 後端：待 PIG-6 開發

## 4. 商業價值（待量化）

> ⚠️ 以下為論述方向，ROI 數字需與和泰/iRent 營運數據對齊後補。

| 價值面向 | 機制 | 預期效益 |
|----------|------|----------|
| **降低爭議成本** | 標準化存證 + AI 比對 | 減少客服人工比圖、縮短爭議處理時間 |
| **提升留存** | 取車落差預告、補拍、即時下架問題車 | 減少「到場才發現問題」的負評 |
| **差異化** | 從「記錄」到「判斷與仲裁」 | 相對 GoSmart 的 AI 層升級 |
| **集團綜效** | 與 yoxi、和泰維修體系連動（中長期） | 裕隆系較難複製的護城河 |

| 週次 | 里程碑 |

### 5.3 3 分鐘 Demo Script（草案）

1. **痛點**（30s）：展示 iRent 現況 — 無引導亂拍、爭議難舉證
2. **取車**（60s）：PoC 虛線引導 → AI 建立基準
3. **還車**（60s）：再拍四角 → AI 標記新增損傷
4. **爭議**（30s）：一鍵 AI 客服整理事證
5. **價值**（30s）：對用戶（自保/積分）、對 iRent（降本/差異化）
